The policy

A client that gets a 503 waits, then tries again. Each wait doubles, so a service that is down for a minute sees a few retries, not a flood. Two numbers set the policy: how many retries, and the first wait.

RetryWait (s)Elapsed (s)
111
223
347
4815

The last retry starts 15 s after the first failure.

The table comes from Backoff.svelte, a component next to this document [1]. The two sliders and their state are written inline, in this file [2].

Note

Without JavaScript the sliders do not move, and the table shows the prerendered policy: 4 retries from 1 s. Every other part of the page is plain HTML.

The change

The policy lives in one function, and the client calls it. This git diff touches two files, so it renders as one block with a unified and split switch [3]. The switch needs JavaScript; without it the diff stays unified.
